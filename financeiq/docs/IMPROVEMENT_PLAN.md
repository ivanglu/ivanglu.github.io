# FinanceIQ improvement plan

Written before the v2 work started. Status of each phase is kept up to date in
[CHANGELOG.md](CHANGELOG.md).

## 1. Audit of version 1

### What exists

| Area | Version 1 |
|---|---|
| Hosting | Static files on GitHub Pages, behind Cloudflare, at `/financeiq/` |
| Stack | Plain HTML, CSS and JavaScript. No framework, no build step, no dependencies |
| Data | `tools/build_data.py` (Python standard library) pulls 10-K figures from the SEC EDGAR XBRL API into one JSON file per company |
| Coverage | 16 companies, 10 fiscal years, 11 line items |
| Features | Two-company picker, scorecard, four chart panels, rule-based plain-English text, AI-written strengths and risks, source tables with 10-K links, a slot for Ivan's analysis |

### What to keep

- The static, dependency-free architecture. It costs nothing to host, has no secrets to leak and a
  student can read every line. Nothing in the v2 scope needs a server.
- SEC EDGAR as the only source of financial data, with values shown as first reported and a link
  to every filing.
- The `#AAPL-MSFT` link format, so existing links keep working.
- The dark visual style shared with the main site.
- The rule that AI text is labelled and Ivan's writing is kept separate from it.

### Problems found

**Financial accuracy**

1. No per-share data. EPS and share counts are missing, and they need stock-split adjustment before
   any multi-year comparison is valid.
2. No interest expense, tax, depreciation, current assets or current liabilities, so interest
   coverage, EBITDA, current ratio and ROIC cannot be calculated.
3. The "Cash" chart tab is really cash plus short-term investments. The label is misleading.
4. Debt excludes lease liabilities. This is stated in the footer but not next to the numbers.
5. "Free cash flow" is operating cash flow minus capital spending. That is a levered figure (it is
   after interest), which is fine for the dashboard but is not free cash flow to the firm and must
   not be fed into an enterprise-value DCF without adjustment.
6. Nike reports no operating income line and three companies report no gross profit. These show as
   "n/a", which is correct, but nothing explains why.
7. Ratios mixing an income-statement number with a balance-sheet number would use the year-end
   balance only. Return ratios should use the average of opening and closing balances.

**Data pipeline**

8. No caching: every run downloads every company again.
9. No consistency checks (for example assets = liabilities + equity).
10. The SEC `User-Agent` contact is a placeholder. The SEC asks for a real contact address.
11. Balance-sheet facts that are missing from a 10-K silently fall back to a later 10-Q. Correct,
    but not recorded anywhere.

**Code**

12. All formulas live inside the UI script, so nothing can be tested without a browser.
13. No automated tests of any kind.
14. One long page. Adding scoring, valuation, trends, benchmarks and research to it would make it
    unusable on a phone.

**Security, performance, accessibility**

15. No secrets, no user data, no third-party scripts: the attack surface is small. All data is
    HTML-escaped before display. A Content-Security-Policy header is missing and worth adding.
16. Page weight is about 60 KB. No performance problem.
17. Charts are mouse/touch only. The data tables are the keyboard and screen-reader alternative, but
    terms such as "operating margin" have no explanation on hover or focus.

## 2. Design decisions for version 2

| Decision | Reason |
|---|---|
| Stay static, no framework, no build step | Maintainable by a student; nothing to pay for or secure |
| Several small pages sharing one script bundle | Each feature gets a URL and can be demonstrated on its own |
| One pure calculation module (`js/calc.js`) with no browser code in it | Every formula can be unit-tested and explained line by line |
| Data pipeline outputs raw reported figures only; all ratios are computed in `calc.js` | One implementation of every formula |
| Stock-split adjustment is detected from the filings themselves | No hand-maintained split table to go stale |
| No stock price feed | No free source was found that is reliable and permits this use. Price is typed in by the user and labelled as such. Valuation multiples are left out of benchmarks for the same reason |
| Peer groups are small, named and fixed | Medians of 7 to 9 named companies are honest. "Industry average" from an unknown universe would not be |
| PDF export uses the browser's print-to-PDF with a print stylesheet | No PDF library to ship or maintain |
| Ivan's writing lives in plain text files that the pages load | He can edit them without touching code, and nothing of his is generated by AI |

## 3. Phases

### Phase 1: Foundation
- Rebuild `build_data.py`: more line items, caching, rate limiting, split detection, data-quality checks, one bundled data file.
- Add four peer groups (Technology, Semiconductors, Retail, Consumer staples), 38 companies in total.
- Fix the issues listed above.

### Phase 2: Core analytics
- `calc.js`: ratios, growth, scoring, DCF.
- Financial Health page: 0 to 100 score, five categories, weight sliders, presets, breakdown, explanations.
- Valuation page: DCF with FCFF bridge, three scenarios, sensitivity matrix.

### Phase 3: Research and analytics
- Historical Trends page: ten metrics, value / growth / indexed views, CAGR.
- Industry Benchmarks page: peer medians and ranks.
- Ivan's Financial Research: three case-study templates with data filled in automatically and Ivan's sections left for him.

### Phase 4: Presentation
- Printable report page and a sample PDF.
- Navigation, glossary tooltips, mobile layout, About page.
- Flagship card on the main site, two-minute guided tour.

### Phase 5: Quality
- Automated tests for `calc.js` and the pipeline.
- Validation of stored figures against the filings themselves.
- Documentation set, including interview preparation.

## 5. Next, in priority order

1. Ivan writes the three case studies and the About sections. Nothing else matters as much.
2. A person reads the AI summaries. Their numbers are checked automatically; their wording is not.
3. Set a real contact address for SEC requests (`FINANCEIQ_CONTACT`).
4. Add lease liabilities as a separate, clearly labelled line, and an "including leases" option for leverage ratios.
5. Check earlier fiscal years against their filings, not only the latest.
6. A scheduled data refresh (GitHub Actions) that opens a pull request when a new 10-K appears.
7. Quarterly and trailing-twelve-month data.
8. A fade from the growth rate to the terminal rate in the DCF, and a per-company discount rate.
9. More peer groups, each with at least eight companies.

## 6. Out of scope, on purpose

- Banks, insurers and REITs. Their statements need different metrics.
- Live prices, analyst estimates, quarterly or trailing-twelve-month data. Version 2 is annual data only and says so.
- Any paid service or server.
- A chatbot.
